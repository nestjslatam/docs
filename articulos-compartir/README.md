reutilizarlos.

| | |
|---|---|
| [`ddd-en-nestjs.md`](ddd-en-nestjs.md) | El artículo largo. Para publicarlo como Discussion de GitHub, en dev.to, o como entrada del blog |
| [`linkedin.md`](linkedin.md) | Tres versiones cortas para LinkedIn, con notas sobre alcance |

## Cómo publicarlo en GitHub

La forma que más tracción da es una **Discussion** en el repositorio
principal, categoría *Show and tell* o *Announcements*:

```
https://github.com/nestjslatam/ddd/discussions/new?category=show-and-tell
```

Pega el contenido de `ddd-en-nestjs.md` tal cual — GitHub renderiza el
Markdown y las tablas sin tocar nada.

Frente a un issue o un README, una Discussion tiene tres ventajas: aparece en
el feed de quien sigue el repositorio, admite comentarios sin ensuciar el
seguimiento de incidencias, y se puede fijar arriba del todo.

## Sobre el tono

Estos textos funcionan porque **cuentan algo cierto y verificable**, incluidos
los errores. Un post que sólo anuncia un producto se ignora; uno que enseña
algo se comparte.

Si adaptas alguno, mantén los números medidos y no los redondees hacia arriba.
Es lo que hace que el resto se lea.
