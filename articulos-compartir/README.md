# Material para compartir

Textos listos para publicar, versionados aquí para poder revisarlos y
reutilizarlos.

| | |
|---|---|
| [`ddd-en-nestjs.md`](ddd-en-nestjs.md) | Artículo técnico. Para Discussion de GitHub, dev.to o el blog |
| [`linkedin-articulo.md`](linkedin-articulo.md) | **Artículo de LinkedIn** (formato largo, se publica desde «Escribir artículo») |
| [`linkedin.md`](linkedin.md) | Posts cortos de feed, para anunciar el artículo |

## La diferencia entre los dos de LinkedIn

No son intercambiables y se usan juntos.

Un **artículo** se publica desde «Escribir artículo», tiene título y portada,
**lo indexa Google** y queda permanente en tu perfil. Es el que construye
reputación: alguien puede encontrarlo dentro de dos años buscando el problema
que resuelve.

Un **post** vive en el feed unos días y sirve para llevar gente al artículo.

El orden que funciona: publicas el artículo, esperas un día, y publicas un post
corto enlazándolo. El post caduca; el artículo se queda.

## Cómo publicarlo en GitHub

La forma que más tracción da es una **Discussion** en el repositorio
principal, categoría *Show and tell* o *Announcements*:

```
https://github.com/nestjslatam/ddd/discussions/new?category=show-and-tell
```

Pega el contenido de `ddd-en-nestjs.md` tal cual — GitHub renderiza el
Markdown y las tablas sin tocar nada.

Frente a un issue o un README, una Discussion tiene tres ventajas: aparece en
el feed de quien sigue el repositorio, admite comentarios sin ensuciar el
seguimiento de incidencias, y se puede fijar arriba del todo.

## Sobre el tono

Estos textos funcionan porque **cuentan algo cierto y verificable**, incluidos
los errores. Un post que sólo anuncia un producto se ignora; uno que enseña
algo se comparte.

Si adaptas alguno, mantén los números medidos y no los redondees hacia arriba.
Es lo que hace que el resto se lea.

## Publicar el artículo en LinkedIn

1. En tu inicio, **«Escribir artículo»** (junto a la caja de publicación)
2. Pega el título como título, y el subtítulo en negrita al comienzo del cuerpo
3. **Sube una portada.** Es lo que más decide si alguien entra: sin ella el
   artículo aparece como un bloque de texto en el feed
4. Los encabezados con `##` van como **Encabezado 2** del editor. LinkedIn no
   admite Markdown: hay que aplicar los estilos con su barra de herramientas
5. Los bloques de código no existen en su editor. Se pegan como texto normal;
   para que se distingan, ponlos en cursiva o en una cita

### Sobre la portada

Ancho recomendado 1280×720. Funciona mejor algo sobrio con el titular en
grande que una foto de archivo: en el feed compite con fotos de gente, y un
titular legible en miniatura gana a una imagen bonita que no se lee.

### Después de publicar

Comparte el artículo como post con dos o tres frases propias — no el resumen
automático. Y responde a todos los comentarios de la primera hora: la
conversación temprana decide cuánto lo sigue mostrando la plataforma.
